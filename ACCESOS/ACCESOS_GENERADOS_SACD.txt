2) CONECTOR SACD ↔ KOHA — OAUTH2 CLIENT CREDENTIALS (PENDIENTE DE GENERAR)
----------------------------------------------------------------------------
Qué es      : API key (CLIENT_ID + CLIENT_SECRET) de KOHA para que el
              conector use OAuth2 en lugar de Basic (lo recomendado para
              producción).
Para qué    : Autenticación del conector sin exponer usuario/clave de staff.
Cómo generar: Ejecutar UNA VEZ el script preparado (habilita el syspref
              RESTOAuth2ClientCredentials, crea la categoría PENDIENTE y
              genera el API key). Desde PowerShell en la raíz del proyecto:

    Get-Content sacd-proyecto\scripts\preparar_koha_vm_oauth2.sh -Raw |
      & "C:\Program Files\PuTTY\plink.exe" -batch -ssh -P 2222 -l root -pw Koha2026 `
        -hostkey "SHA256:5k9CzL7vO283XRQDBsE+K2HGwyjiIKeWX/fQMbrhu6Y" 127.0.0.1 "tr -d '\r' | bash"

              ⚠ GUARDAR el CLIENT_SECRET impreso (no se puede recuperar) y
              anotarlo AQUÍ y en appsettings.KohaVM.json (ClientId/ClientSecret,
              TipoAutenticacion="OAuth2").

CLIENT_SECRET: (pendiente)

4) JWT DEL CONECTOR SACD (clave de desarrollo)
----------------------------------------------------------------------------
Qué es      : Clave HMAC-SHA256 con la que la API SACD firma los tokens de
              sesión y los QR de los carnets.
Para qué    : Solo DESARROLLO. En producción hay que generar una clave larga
              aleatoria y ponerla en variable de entorno Jwt__ClaveSecreta
              (NUNCA en el repo).
Dónde vive  : sacd-proyecto\src\ConectorApi\appsettings.json → Jwt:ClaveSecreta
